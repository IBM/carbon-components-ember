# Carbon's React API in Ember

Carbon's website, its Figma kits and most of what agents know about Carbon describe `@carbon/react`. The components here follow its API, so what those sources say carries over with Ember's syntax. Look up each component in [components.md](components.md) for its exact arguments and blocks, because a few don't match React yet.

- **Imports.** `import { TextInput } from '@carbon/react'` becomes `import { TextInput } from 'carbon-components-ember/components'`, and `import { LineChart } from '@carbon/charts-react'` becomes `import { LineChart } from 'carbon-components-ember/charts'`. Each component's reference shows its import.
- **Props** become arguments with the same names and values: `labelText="Name"` is `@labelText="Name"`. Booleans and numbers go in double curly braces: `disabled` is `@disabled={{true}}`, `max={10}` is `@max={{10}}`.
- **`className` and pass-through attributes** (`aria-*`, `data-*`, `autocomplete`) are plain attributes on the component: `class="wide"`. Where React puts `className` on a different element from its other props, as TextInput does (its wrapper, and the `<input>`), `className` is `@className`, and `class` and the other attributes go where React puts the rest; the component's arguments list `className` when it takes one. A prop the component declares, such as TextInput's `id` or RadioButton's `name`, stays an argument (`@id`, `@name`).
- **`children`** are the default block: `<Tag>Beta</Tag>`.
- **Parts used as children**, such as `AccordionItem` or `AILabelContent`, are usually yielded by their parent, already wired to it: `<Accordion as |Item|><Item @title="Plan">…</Item></Accordion>`.
- **A prop that takes an element**, such as `decorator={<AILabel>…</AILabel>}`, is a named block that yields the part: `<:decorator as |AILabel|><AILabel as |label|><label.Content>…</label.Content></AILabel></:decorator>`.
- **A prop that takes a component**, such as `renderIcon={Add}`, takes it as an argument: `@renderIcon={{Add}}`.
- **A router link in `as` or `element`**, as React apps pass their router's `Link`, is `@route` instead, with `@models` and `@query` as on Ember's `LinkTo`: `<Button @route="user" @models={{array user.id}}>`. Link, Button, BreadcrumbItem, OverflowMenuItem, Card, Tag, a `@clickable` Tile, TreeView's nodes and the UI Shell's links take them, and the UI Shell's `@menuItems` and AI Chat Toolbar's actions take `route`, `models` and `query` keys; `@href` stays for other URLs.
- **Icons.** `import { Add } from '@carbon/icons-react'` and `<Add size={16} />` become `import Add from 'carbon-components-ember/components/icons/add'` and `<Add @size="16" />`. The module is the React name in kebab case, and an icon's `className` is `@svgClass`.
- **Render props**, such as DataTable's `{({ rows, headers, getTableProps }) => …}`, are yielded components: `<DataTable as |table|>` yields `<table.Table>`, `<table.Header>` and `<table.EachBodyRows>`. The component's reference shows its arguments and how the parts fit together.
- **Callbacks**: `onChange={handler}` is `@onChange={{this.handler}}`. An event the element has, such as `onClick` on a Button or a TextInput, is `{{on "click" this.handler}}` on the component. Check the argument's type in the reference for what a callback receives.
- **Controlled and uncontrolled** components take the same arguments as in React, where they have them: `@value` with `@onChange`, or `@defaultValue`.
- **`useState`** is a `@tracked` property on a Glimmer component class.
- **`useRef` and `useEffect`** on an element become a modifier on the component, which `...attributes` forwards to its element.
- **Conditionals and lists**: `{isOpen && <X />}` is `{{#if this.isOpen}}<X />{{/if}}`, and `items.map((item) => …)` is `{{#each this.items as |item|}}…{{/each}}`.
