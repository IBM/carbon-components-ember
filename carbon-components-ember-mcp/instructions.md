## carbon-components-ember

This app's UI uses carbon-components-ember: IBM's Carbon Design System as Ember components, with the same components, arguments and behaviour as Carbon React.

- **Look components up before using them.** The carbon-components-ember MCP server's `docs-list` tool lists the components; `docs-show` gives one component's import, arguments, blocks and examples. Arguments follow Carbon React's props (`labelText` is `@labelText`), but a few components don't match React yet, so use only what `docs-show` documents. Without the server, read the component's signature in `node_modules/carbon-components-ember/declarations/components/<name>.d.ts`.
- **Write Ember, not React.** Components are invoked with angle brackets in `.gts` templates. Props become `@` arguments, callbacks included (`@onClick`, `@onChange`), and `children` become blocks. Components forward `...attributes`, so `class`, `aria-*` and modifiers such as `{{on}}` go on the component itself.
- **Icons are components**, named as in `@carbon/icons-react`. Import each one from `carbon-components-ember/components/icons/<name>`, its React name in kebab case, and give it a `@size`: `import CheckmarkFilled from 'carbon-components-ember/components/icons/checkmark-filled'`, then `<CheckmarkFilled @size="16" />`.
- **Type-check what you write.** After editing `.gts` files, run the app's Glint check (`ember-tsc --noEmit`, often the `lint:types` script) and fix every error. Glint checks each component's arguments, blocks and attributes, so an error there usually means a wrong or misspelled argument. Look the component up again rather than casting the error away.
- **Setup.** The app loads `@carbon/styles/css/styles.css` and `carbon-components-ember/styles.scss` once, and its application template renders `<div id="ember-basic-dropdown-wormhole"></div>` and `<div id="carbon-components-dialog-id"></div>`. If a Dropdown's menu or a confirmation dialog doesn't appear, check these first.
